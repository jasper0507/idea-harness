# 词汇表

## 内部术语

以下术语在 skill 文件中使用，不得暴露给用户。

| 术语 | 定义 |
|------|------|
| **门槛** (Gate) | 七个必需澄清检查点之一。全部通过才能进入 Ready。 |
| **精确度缺口** (Precision Gap) | 门槛已有回答，但回答不够精确，无法安全实现。 |
| **隐藏默认值** (Hidden Default) | 用户未明确确认，但其回答暗含的假设。 |
| **危险假设** (Dangerous Assumption) | 默认阻止列表中的内容（登录、支付、AI 等），下游 agent 可能擅自添加。 |
| **验收行为** (Acceptance Behavior) | 可检查的动作或可见结果，定义"V1 能用"。 |
| **范围边界** (Scope Boundary) | V1 不做的事项 + 不做的原因。区别于无原因的"不做列表"。 |
| **阻断条件** (Blocking Condition) | 必须解除才能继续推进的冲突、矛盾或未确认假设。 |
| **决策树** (Decision Tree) | 门槛之间的依赖关系，决定下一个应该问哪个门槛。 |
| **行为契约** (Behavior Contract) | 执行 Prompt 中对系统行为的描述，强调"做什么"而非"用什么 UI 元素"。 |

## 用户用语规范

### 原则

- 镜像用户的用词。用户说"记一下"就用"记"，不改成"录入"。
- 不引入用户没用过的专业词汇：MVP、PRD、spec、use case、user story、stakeholder、acceptance test。
- 当用户用了模糊词，不直接替换，追问它在他的场景里具体指什么。

### 常见歧义词处理

| 用户常说的词 | 可能的不同含义 | 应该追问的方向 |
|-------------|---------------|---------------|
| "保存" | 浏览器本地 / 文件 / 云端 / 数据库 | "下次打开还在吗？换设备呢？" |
| "通知" | 浏览器推送 / 邮件 / 短信 / 页面内提示 | "在哪里看到这个通知？" |
| "管理" | 增删改查 / 统计 / 审批 / 归档 | "管理的时候你具体做什么动作？" |
| "记录" | 文字 / 数字 / 图片 / 时间线 | "记下来的一条长什么样？" |
| "分享" | 发链接 / 截图 / 协作编辑 / 权限控制 | "对方看到后能做什么？" |
| "同步" | 多设备 / 多人 / 实时 / 备份 | "换设备也要看到？还是怕丢？" |
| "提醒" | 定时弹窗 / 邮件 / 页面标记 / 手动查看 | "谁提醒你？在哪里看到？" |
| "学习" | 看内容 / 做题 / 记笔记 / 打卡 / 追踪进度 | "学习的时候你手上在做什么？" |
| "简单" | 功能少 / 操作步骤少 / 界面干净 / 开发快 | "简单是指用起来步骤少，还是功能少？" |

### 用户可见输出中避免的词汇

- 技术术语：API、CRUD、localStorage、数据库、前端、后端、部署、SDK
- 流程术语：MVP、PRD、需求规格、验收测试、利益相关者、用例
- 内部术语：门槛、精确度缺口、阻断条件、状态机、Harness Gate、行为契约
