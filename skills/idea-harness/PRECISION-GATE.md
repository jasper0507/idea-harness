# 精确度检查

当七个门槛都有回答时，逐一运行以下四项检查。任一项未通过，状态为 `needs-precision`，而不是 `ready`。

精确度检查拦住这种情况：**用户对每个门槛都给了回答，但回答不够精确，无法安全交给下游 agent 实现。**

## 四项检查

### 1. 目标一致性

用户的回答是否始终指向同一个目标？同一个词是否总是指同一件事？

检查方法：

- 回顾用户用过的关键词。如果同一个词在不同回答中可能指不同的东西 → 追问具体含义。
- 检查用户说的目标与他要求的功能是否一致。如果目标是"省时间"但功能实际更花时间 → 指出。
- 如果用户和 agent 可能对某个词的理解不同 → 用用户的场景重新定义它。

示例：

- 用户先说"记录学习内容"，后来又说"记录学习进度"。"内容"和"进度"是同一件事吗？
- 用户说"通知"。是浏览器弹窗？微信消息？页面内提示？
- 用户说目标是"快速记账"，但要求的功能包含分类、标签、备注、拍照 → 功能与"快速"目标冲突。

### 2. 隐藏默认值

用户的回答是否暗含他没有明确确认的假设？

检查方法：

- 扫描每个门槛答案，寻找暗含的默认阻止列表内容。
- 检查答案是否假设了特定技术行为："保存"是否暗含数据库？"同步"是否暗含云端？"登录"是否暗含账号体系？
- 检查答案是否假设了未讨论的用户行为："分享给朋友"是否暗含分享链接生成？

示例：

- 用户说"下次打开还在" → 浏览器本地存储 vs 云端，需要追问。
- 用户说"每个人看自己的" → 暗含账号登录，必须明确确认。
- 用户说"自动提醒我" → 暗含通知权限或后台服务，必须明确确认。

### 3. 场景走查

能否从头到尾走完一个具体使用场景，而不碰到未决定的分叉？

检查方法：

- 构造一个从打开应用到完成主动作的完整场景。
- 每一步检查：用户需要做什么？系统需要做什么？数据去哪里？
- 如果某一步碰到"这里还没定" → 追问那一步。

示例：

- 记账工具：打开 → 选分类 → 填金额 → 记一笔 → 列表里看到 → 关闭 → 重新打开 → 列表还在。每一步都有对应的已确认行为吗？
- 如果"关闭后重新打开"这一步没有确认 → 追问数据行为。
- 如果"选分类"的分类从哪来没有确认（固定？自定义？） → 追问。

### 4. 矛盾扫描

已确认答案之间是否存在矛盾？

检查方法：

- 把所有已确认事实放在一起，逐对检查。
- 特别关注：门槛 4（主动作）与门槛 6（范围边界）是否冲突？门槛 5（数据行为）与门槛 6 是否冲突？
- 如果发现矛盾 → 状态变为 `blocked`，追问只问冲突点。

示例：

- 用户说"第一版不需要登录"但也说"每个人看自己的内容" → 矛盾。
- 用户说"只在这台电脑用"但也说"手机上也想看" → 矛盾。
- 用户说"不需要分类"但验收标准写了"能按分类查看" → 矛盾。

## 追问策略

精确度追问和门槛追问不同：

- **门槛追问**打开新维度："我们还没聊到数据保存的问题。"
- **精确度追问**收紧已有维度："你说的'记录'，具体是指记下金额，还是金额加上时间和分类？"

精确度追问时，优先使用这三种问法：

- **假设暴露**：指出答案里藏着的未检验前提。
- **场景走查**：在具体步骤中指出模糊点。
- **对比锚定**：用不同实现的差异帮用户看清自己真正想要什么。

## 通过条件

四项检查全部通过 = 没有术语歧义 + 没有隐藏默认值 + 场景可完整走通 + 没有矛盾。

此时状态才可以转为 `ready`。
