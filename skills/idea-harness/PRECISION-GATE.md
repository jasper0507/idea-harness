# 精确度检查

当七个门槛都有回答时，逐一运行以下四项检查。任一项未通过，状态为 `needs-precision`，而不是 `ready`。

拦住这种情况：**用户对每个门槛都给了回答，但回答不够精确，无法安全交给下游 agent 实现。**

## 四项检查

### 1. 目标一致性

用户的回答是否始终指向同一个目标？同一个词是否总是指同一件事？

- 回顾关键词。同一个词在不同回答中可能指不同的东西 → 追问具体含义。
- 目标与功能是否一致。目标是"省时间"但功能实际更花时间 → 指出。
- 用户和 agent 对某个词理解不同 → 用用户的场景重新定义。

示例："记录学习内容"与"记录学习进度"——"内容"和"进度"是同一件事吗？用户说目标"快速记账"，但要求分类、标签、备注、拍照 → 与"快速"冲突。

### 2. 隐藏默认值

用户的回答是否暗含未明确确认的假设？

- 扫描每个门槛答案，寻找暗含的默认阻止列表内容。
- "保存"是否暗含数据库？"同步"是否暗含云端？"登录"是否暗含账号体系？
- "分享给朋友"是否暗含分享链接生成？

示例："下次打开还在" → 浏览器本地 vs 云端，需追问。"每个人看自己的" → 暗含账号登录。"自动提醒我" → 暗含通知权限或后台服务。

### 3. 场景走查

能否从头到尾走完一个具体使用场景，而不碰到未决定的分叉？

- 构造从打开应用到完成主动作的完整场景。
- 每一步：用户做什么？系统做什么？数据去哪里？
- 某一步碰到"这里还没定" → 追问那一步。

示例：记账工具 — 打开 → 选分类 → 填金额 → 记一笔 → 列表看到 → 关闭 → 重新打开 → 列表还在。如果"关闭后重新打开"未确认 → 追问。如果"选分类"的分类来源未确认 → 追问。

### 4. 矛盾扫描

已确认答案之间是否存在矛盾？

- 把所有已确认事实放在一起逐对检查。
- 重点：门槛 4（主动作）与 6（范围边界）是否冲突？门槛 5（数据行为）与 6 是否冲突？
- 发现矛盾 → 状态变为 `blocked`。

示例："不需要登录"但"每个人看自己的内容" → 矛盾。"只在这台电脑用"但"手机上也想看" → 矛盾。

## 追问策略

精确度追问收紧已有维度（"你说的'记录'，具体是指记下金额，还是金额加上时间和分类？"），门槛追问打开新维度（"我们还没聊到数据保存的问题"）。

精确度追问优先使用：**假设暴露**、**场景走查**、**对比锚定**。

## 通过条件

四项全部通过 = 没有术语歧义 + 没有隐藏默认值 + 场景可完整走通 + 没有矛盾。此时状态才可以转为 `ready`。
