# 状态机

每一轮内部运行都必须确定当前状态。状态决定输出格式和下一步行为。

## 四个状态

### gathering

还有门槛未被回答。继续按决策树优先级提问。输出：Need More Info。

### needs-precision

所有七个门槛都有回答，但至少一个未通过精确度检查（→ PRECISION-GATE.md）。输出：Need More Info，追问指向精确度缺口。

拦住"表面完整但不够精确"的需求被判定为 Ready。

### blocked

检测到以下任一阻断条件：

- 用户对 V1 说"都要"且未确认优先级。
- 用户说"你决定"且未确认推荐方案。
- 已有答案之间存在冲突。
- 某个答案暗含默认阻止列表中的假设，但用户没有确认。
- 验收标准不可检查。

输出：Need More Info，追问专门指向阻断条件。

### ready

所有七个门槛已回答 + 全部精确度检查通过 + 无阻断条件。输出：需求简报（默认）。执行 Prompt 仅在用户明确要求时追加。

## 转移规则

```
gathering ──[仍有门槛缺失]──→ gathering
gathering ──[门槛完整，精确度未通过]──→ needs-precision
gathering ──[门槛完整 + 精确度全通过]──→ ready
gathering ──[检测到阻断条件]──→ blocked

needs-precision ──[仍不够精确]──→ needs-precision
needs-precision ──[全部精确度通过]──→ ready
needs-precision ──[发现新冲突或隐藏假设]──→ blocked

blocked ──[阻断解除，仍有门槛缺失]──→ gathering
blocked ──[阻断解除，精确度未通过]──→ needs-precision
blocked ──[阻断解除，全部通过]──→ ready

ready ──[用户引入新需求或修改已确认内容]──→ gathering
```

## 每轮判定顺序

1. 提取本轮新确认事实，更新门槛状态。
2. 检查阻断条件 → 如果是 → `blocked`。
3. 检查门槛是否有缺失 → 如果是 → `gathering`。
4. 对所有已回答门槛运行精确度检查 → 如果任一未通过 → `needs-precision`。
5. 全部通过 → `ready`。

## 决策树优先级

门槛不是按 1–7 顺序线性检查。每轮按以下优先级选择下一个问题：

1. 处于 `blocked`：先解除阻断。
2. 门槛 1（问题/痛点）未明确：必须先问。没有清楚的痛点，后续全部无法判断。
3. 门槛 1 已明确但 2（用户）或 3（场景）未明确：优先问能决定后续分支走向的那个。
4. 门槛 4（第一版主动作）依赖于 2/3 的答案：先问 2/3。
5. 门槛 5（数据行为）通常在 4 确定后再问。
6. 门槛 6（范围边界）在主功能确定后自然产生。
7. 门槛 7（验收标准）最后确认。

如果用户的回答揭示了某个后续门槛的关键分叉（例如提到"多人用"直接影响门槛 2 和 6），立即跳转。

## 状态回退

`ready` 是唯一可以回退的状态：用户在 Ready 后修改已确认内容，状态回到 `gathering`。

`needs-precision` 不能跳过直接到 `ready`：必须逐项通过精确度检查。
