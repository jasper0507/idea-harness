# Idea Harness

> **大多数模糊想法死在 AI 第一轮脑补。**
> Idea Harness 专门在这一步给 AI **套上缰绳**。

**一个极窄的澄清 Skill**：把非程序员一句模糊的"小应用想法"，**澄清到 AI 可以安全执行、但绝不乱猜** 的程度。

简体中文 | [English](README.en.md)

---

## 问题

当前大多数 AI Coding Agent（Claude Code、Cursor、Codex 等）遇到下面这类输入时：

```text
我想做一个学习管理网站。
我想做一个记账 App。
我想做一个家庭任务打卡工具。
```

它们会立刻开始**脑补**：
- 账号系统、数据库、推送通知、统计图表、后台管理……
- 各种你根本没想要的功能和复杂架构

结果就是：**做出来一个你不想要的东西**，或者项目直接崩掉。

Andrej Karpathy 曾指出：**LLM 特别喜欢在没有确认的情况下擅自做假设**。Idea Harness 正是针对这个早期最大痛点而生。

---

## 解决方案

**Idea Harness 只做一件事** —— **需求澄清**。

它把 Karpathy 的"Think Before Coding"哲学 + Harness Engineering 的控制环，**极致窄化**成一个专注早期阶段的轻量 Skill。

核心机制：
- 只认用户明确说过的事实（证据账本）
- 严格禁止危险假设
- 每次只问**一个最关键的问题**
- 使用 `Status: Need More Info` / `Ready` 门禁控制流程

---

## 与其他 Skill 的核心区别

| 维度 | Idea Harness | 大多数其他 Skill / Agent |
|------|--------------|-------------------------|
| **定位** | **极窄** - 只做需求澄清 | 全流程 / 执行 / 代码生成 |
| **核心原则** | **严禁脑补**，只认已确认事实 | 鼓励创意、主动补全功能 |
| **适用阶段** | **想法最模糊的第 0 步** | 已经有一定清晰度之后 |
| **风险控制** | 极强（Status 门禁 + 边界保护） | 较弱 |
| **轻量程度** | **纯 Skill**，极致轻量 | 常带框架、测试、多文件 |

**一句话总结**：
别人教 AI **怎么做**，Idea Harness 教 AI **先问清楚再做**。

## 输出示例

**Need More Info 阶段**（典型输出）：

```markdown
## 当前结论
Status: Need More Info
Reason: "学习管理网站"范围太宽，最容易跑偏的是核心管理对象。

## 已确认
- 你想做一个学习管理相关的网站。

## 不能先假设
- 不能假设有登录、数据库、课程表、积分系统等。

## 下一步
你最想先管理哪一类学习内容？
A. 每天要完成的学习任务
B. 作业和截止日期
C. 学习笔记和资料
D. 学习时间与打卡记录
```

只有所有关键边界（目标、使用者、核心流程、第一版范围、不做的事等）都确认后，才会输出 `Status: Ready`。

## 设计原则

- **窄一点，比全能更有用** —— 专精于澄清阶段
- **问少一点，比问全更容易推进**
- **先定边界，再让 AI 实现**
- 融合 **Harness Engineering**（给 AI 套缰绳） + **Karpathy 哲学**（Think Before Coding）

---

## 使用场景

**推荐使用**：
- 你只有一句模糊想法
- 你是技术小白，不知道怎么把 idea 变成需求
- 你想做一个**极小但正确**的第一版
- 你害怕 AI 自作主张

**不适合**：
- 已经有清晰 PRD
- 需要立即写代码或选技术栈
- 需要商业模式或完整产品规划
